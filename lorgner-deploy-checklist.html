Supabase — Database & Auth
Set up your database, authentication, and storage before anything else
Create Supabase project
Go to supabase.com → New Project → Name it lorgner → Choose a strong database password and save it somewhere safe → Select region closest to your users (US East for New York audience)
Supabase
Run the schema SQL
In your Supabase project → SQL Editor → New Query → Paste the entire contents of lorgner-schema.sql → Click Run. This creates all 4 tables, all RLS policies, and the storage bucket in one step.
Supabase
Verify schema ran correctly
In SQL Editor run: SELECT table_name FROM information_schema.tables WHERE table_schema = 'public' — you should see members, glasses, sessions, events. Then check Storage → Buckets — you should see glasses-photos.
Supabase
Configure Auth settings
Authentication → Settings → Site URL: set to your Lorgner domain e.g. https://lorgner.com. Redirect URLs: add https://lorgner.com/*. Email → enable magic link. Disable email confirmation (members confirm by clicking magic link). Set JWT expiry to 604800 (7 days).
Supabase
Copy your Supabase credentials
Project Settings → API. Copy three values and save them securely: Project URL (your SUPABASE_URL), anon public key (safe for frontend), and service_role key (keep secret — backend only, never in frontend code).
Supabase
2
Railway — Backend Proxy
Deploy the proxy that hides your Claude API key and verifies members
Create Railway account and project
Go to railway.app → Sign up → New Project → Deploy from GitHub repo OR upload files directly. Create a new empty service. Railway auto-detects Node.js from package.json.
Railway
Upload server files
Upload lorgner-proxy-server.js as server.js and lorgner-package.json as package.json to your Railway service. Railway reads package.json and installs dependencies automatically on deploy.
Railway
Set Railway environment variables
In Railway → your service → Variables tab. Add all five variables exactly as shown:
Railway Environment Variables
ANTHROPIC_API_KEYsk-ant-... (your Claude API key)
SUPABASE_URLhttps://your-project.supabase.co
SUPABASE_SERVICE_KEYeyJ... (service role key — keep secret)
ALLOWED_ORIGINhttps://lorgner.com
RATE_LIMIT_MAX20
STRIPE_SECRET_KEYsk_live_... (from Stripe dashboard)
STRIPE_WEBHOOK_SECRETwhsec_... (from Stripe webhook setup)
Railway
Deploy and verify health check
Railway deploys automatically after variables are set. Once deployed, copy your Railway URL (e.g. lorgner-proxy.up.railway.app) and visit /health in your browser. You should see: {"status":"Lorgner is ready."}. If you see that, the proxy is live.
Railway
Copy Railway URL into frontend
Open lorgner-frontend.html → find the CONFIG block near the top of the script section → replace https://your-lorgner-proxy.railway.app/chat with your actual Railway URL followed by /chat.

Stripe — Payments
Set up the founding member checkout and webhook that creates accounts
Create Stripe account
Go to stripe.com → Create account → Complete business verification with your legal name and SSN (same information as your W-9 for affiliate networks). Stripe pays out to your bank account on a rolling basis.
Stripe
Create the founding member product
Stripe Dashboard → Products → Add Product → Name: "Lorgner Founding Membership" → Price: $29.00 → Recurring → Monthly. Note the Price ID (looks like price_1ABC...) — you need this for Stripe Checkout.
Stripe
Create Stripe Checkout session endpoint
Add a POST /create-checkout-session endpoint to your Railway proxy. It creates a Stripe Checkout URL and returns it to the frontend. The frontend redirects the user to that URL. Stripe handles the payment form. On success Stripe calls your webhook. The payment page in the frontend prototype currently simulates this — wire it up to this endpoint when ready.
Stripe
Set up Stripe webhook
Stripe Dashboard → Developers → Webhooks → Add endpoint. URL: https://your-railway-url.up.railway.app/stripe-webhook. Select events: checkout.session.completed, customer.subscription.deleted, invoice.payment_failed. After creating, copy the Signing Secret and add it to Railway as STRIPE_WEBHOOK_SECRET.
Stripe
Test payment flow end to end
Use Stripe's test mode. Test card: 4242 4242 4242 4242, any future expiry, any CVC. Complete a test checkout → verify Stripe Dashboard shows the event → verify Railway logs show account creation → verify Supabase shows new user in Auth → verify magic link email arrives.
Stripe
4
Vercel — Frontend
Deploy the Lorgner experience to your domain
Update frontend config values
Open lorgner-frontend.html and update the three CONFIG values: SUPABASE_URL (your project URL), SUPABASE_ANON_KEY (the public anon key — safe in frontend), and PROXY_URL (your Railway URL + /chat). These are the only three values that need changing.
Local
Create Vercel account and deploy
Go to vercel.com → New Project → Import from GitHub or drag and drop your file. Vercel serves the HTML file at your domain. For a single HTML file the simplest approach is to put it in a folder called public and deploy that folder. Vercel Hobby plan is free and sufficient until you monetize.
Vercel
Connect your lorgner.com domain
Vercel → your project → Settings → Domains → Add lorgner.com. Vercel gives you two DNS records to add in Cloudflare (where you registered the domain). Add both records, propagation takes 5–30 minutes. Then test that https://lorgner.com loads your frontend.
Domain
Update ALLOWED_ORIGIN in Railway
Now that your domain is live, go back to Railway → Variables → change ALLOWED_ORIGIN from https://lorgner.com to your actual domain if it differs. Railway redeploys automatically. Test that the frontend can call the proxy without CORS errors by opening browser dev tools → Network tab → clicking Consult Lorgner.
Railway
Update Supabase Site URL and Redirect URLs
Supabase → Authentication → Settings → Site URL: change to https://lorgner.com. Redirect URLs: confirm https://lorgner.com/* is listed. This ensures magic links redirect to the correct domain after a member clicks them.
Supabase
5
Launch Verification
Test every flow end to end before inviting founding members
Complete new member flow
On a fresh browser (or incognito) go to lorgner.com. Complete the payment form with Stripe test card. Verify you land on the welcome screen. Verify you receive a magic link email. Click it. Verify you land on the dashboard. Verify your account appears in Supabase Auth.
Test
Test collection upload and persistence
In the dashboard → My Collection → add a pair by uploading a photo. Give it a name. Verify it appears in the grid. Close the browser entirely. Sign back in via magic link. Verify the pair is still there — it should load from Supabase, not from memory.
Test
Test consultation flow
With a pair in your collection → click Consult Lorgner → type an occasion → verify Lorgner responds. Open browser Network tab and confirm the request goes to your Railway URL, not to api.anthropic.com directly. Confirm no API key is visible in any network request headers or responses.
Test
Test protection layers
In the chat type something off-topic — ask about the weather or politics. Verify Lorgner redirects rather than answering. Try the sign-in page with an email not in Supabase and verify it handles gracefully. Try refreshing the page mid-session and verify the JWT keeps you logged in.
Test
Verify data capture in Supabase
After a consultation → Supabase dashboard → Table Editor → sessions. Verify a row was written with your user_id, the occasion text, Lorgner's reply, and the pair count. Check Table Editor → glasses. Verify your pair is stored with the correct photo_path. This confirms your data capture is working.
Supabase
Switch Stripe to live mode
Stripe Dashboard → toggle from Test to Live mode. Create a new webhook endpoint in live mode at the same Railway URL. Update Railway env vars STRIPE_SECRET_KEY and STRIPE_WEBHOOK_SECRET with the live mode values. Test with a real card using a $1 product first if you want to confirm live payments work before your founding member rate.
Stripe
Invite your first founding member
Send the first personal email to someone in your network who fits the Lorgner demographic. Direct them to lorgner.com. Watch Railway logs in real time as they sign up, upload their collection, and consult Lorgner. Your first real session tells you more than any amount of testing.
Launch
Monitor first week
Check Railway logs daily for errors. Check Supabase sessions table for session data. Check Stripe dashboard for subscription status. Check that magic link emails are arriving (Supabase sends via their email infrastructure by default — switch to a custom domain sender like Resend.com for better deliverability). Note every question Lorgner gets asked and every gap it identifies — this is your product research.
